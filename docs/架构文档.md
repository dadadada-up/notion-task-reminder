## 系统概述

Notion Task Manager 是一个基于 Notion API 的任务管理和提醒系统，支持多渠道通知推送。

### 核心功能

1. **任务管理**: 从 Notion 数据库获取和管理任务
2. **智能提醒**: 定时发送待办和已完成任务提醒
3. **多渠道推送**: 支持 PushPlus、WxPusher、邮件等多种通知方式
4. **Web 管理**: 提供现代化的 Web 界面进行配置和管理
5. **自动化**: 通过 GitHub Actions 实现定时任务自动化

## 模块设计

### 1. 核心模块 (backend/core/)

#### config.py
**职责**: 统一配置管理

**类设计**:
```python
Settings
├── NotionConfig      # Notion 配置
├── PushConfig        # 推送配置
├── EmailConfig       # 邮件配置
├── GitHubConfig      # GitHub 配置
├── WebConfig         # Web 服务配置
└── RuntimeConfig     # 运行时配置
```

**功能**:
- 从环境变量加载配置
- 配置验证
- 配置脱敏
- 配置持久化

### 2. 服务层 (backend/services/)

#### notion_service.py
**职责**: Notion API 交互

**主要方法**:
- `get_tasks()`: 获取任务列表
- `get_tasks_for_notification()`: 获取用于通知的任务
- `get_task_stats()`: 获取任务统计

#### push_service.py
**职责**: 推送通知服务

**主要方法**:
- `send_pushplus()`: PushPlus 推送
- `send_wxpusher()`: WxPusher 推送
- `format_message()`: 消息格式化

#### email_service.py
**职责**: 邮件发送服务

**主要方法**:
- `send_email()`: 发送邮件
- `format_html()`: HTML 格式化

#### config_service.py
**职责**: 配置管理服务

**主要方法**:
- `get_config()`: 获取配置（已脱敏）
- `update_config()`: 更新配置

#### schedule_service.py
**职责**: 定时任务管理

**主要方法**:
- `get_schedules()`: 获取定时任务
- `save_schedules()`: 保存定时任务
- `update_workflow()`: 更新 GitHub Actions

#### github_service.py
**职责**: GitHub API 交互

**主要方法**:
- `update_workflow_file()`: 更新 workflow 文件
- `create_commit_comment()`: 创建提交评论

### 3. API 层 (backend/app.py)

**路由设计**:
```
GET  /health              # 健康检查
GET  /api/tasks           # 获取任务
GET  /api/tasks/stats     # 任务统计
POST /api/notify          # 发送通知
GET  /api/schedule        # 获取定时任务
POST /api/schedule        # 保存定时任务
GET  /api/config          # 获取配置
PUT  /api/config          # 更新配置
GET  /*                   # 前端静态文件
```

## 数据流

### 1. 任务获取流程

```
用户请求
  │
  ▼
Web 前端/CLI
  │
  ▼
Flask API
  │
  ▼
NotionService
  │
  ▼
Notion API
  │
  ▼
数据处理
  │
  ▼
返回结果
```

### 2. 通知发送流程

```
定时触发/手动触发
  │
  ▼
获取任务 (NotionService)
  │
  ▼
格式化消息 (PushService/EmailService)
  │
  ├─▼ PushPlus API
  ├─▼ WxPusher API
  └─▼ SMTP Server
  │
  ▼
发送结果汇总
  │
  ▼
返回/记录
```

### 3. 配置更新流程

```
用户修改配置
  │
  ▼
前端验证
  │
  ▼
API 请求 (PUT /api/config)
  │
  ▼
ConfigService.update_config()
  │
  ├─▼ 更新内存配置
  ├─▼ 保存到 .env 文件
  └─▼ 重新加载环境变量
  │
  ▼
返回成功
```
