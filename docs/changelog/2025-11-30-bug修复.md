## Bug 1: 编辑页面状态更新时任务完成时间未更新

### 问题描述
- 当在编辑页面（TaskModal）将任务状态改为"已完成"时，数据库中的任务完成时间（completed_time）没有更新
- 但通过页面上"进行中"任务的复选框点击完成时，完成时间可以正确更新

### 根本原因
- TaskModal 组件的 handleSubmit 函数中缺少自动设置 completed_time 的逻辑
- formData 状态定义中缺少 completed_time 字段

### 修复方案
1. 在 `frontend/src/components/TaskModal.tsx` 中添加 completed_time 字段到 formData 状态
2. 在 handleSubmit 函数中添加逻辑：当状态改为"已完成"且之前不是"已完成"时，自动设置当前时间为完成时间

### 修改文件
- `frontend/src/components/TaskModal.tsx`

### 关键代码
```typescript
// 如果状态改为已完成，自动设置完成时间
const dataToSave = { ...formData }
if (formData.status === '已完成' && (!task || task.status !== '已完成')) {
  dataToSave.completed_time = new Date().toISOString()
}

await onSave(dataToSave)
```

## Bug 2: 时区转换问题导致时间显示不一致

### 问题描述
- Notion数据库显示：2025年11月30日 20:58
- 前端详情页显示：2025年12月1日 04:58（多加了8小时）
- 前端卡片显示：只显示日期，没有显示时间

### 根本原因
使用了错误的时区转换方式：
```typescript
// ❌ 错误方式
const beijingTime = new Date(date.getTime() + (8 * 60 * 60 * 1000))
```

这导致：
1. Notion API返回的时间已经是ISO格式的UTC时间
2. 前端代码错误地又加了8小时
3. TaskTable组件使用了 `formatDate()` 而不是 `formatDateTime()`

### 修复方案

#### 方案1：使用 Intl API（已实施但发现问题）
```typescript
// 使用 Intl API 转换为北京时间
const options: Intl.DateTimeFormatOptions = {
  timeZone: 'Asia/Shanghai',
  year: 'numeric',
  month: 'numeric',
  day: 'numeric',
  hour: '2-digit',
  minute: '2-digit',
  hour12: false
}

const parts = new Intl.DateTimeFormat('zh-CN', options).formatToParts(date)
```

#### 方案2：直接显示UTC时间（最终方案）
```typescript
// 直接显示数据库的值，不做时区转换
const formatCompletedTime = (dateString: string | undefined) => {
  if (!dateString) return '-'
  try {
    const date = new Date(dateString)
    if (isNaN(date.getTime())) return dateString
    
    const year = date.getUTCFullYear()
    const month = String(date.getUTCMonth() + 1).padStart(2, '0')
    const day = String(date.getUTCDate()).padStart(2, '0')
    const hours = String(date.getUTCHours()).padStart(2, '0')
    const minutes = String(date.getUTCMinutes()).padStart(2, '0')
    
    return `${year}年${month}月${day}日 ${hours}:${minutes}`
  } catch (error) {
    return dateString
  }
}
```

### 修改文件
1. `frontend/src/utils/dateFormat.ts` - 所有日期格式化函数
2. `frontend/src/components/TaskTable.tsx` - 导入并使用 `formatDateTime`
3. `frontend/src/components/TaskDetailModal.tsx` - 使用 `formatDateTime`
4. `frontend/src/components/TaskGallery.tsx` - 使用 `formatDateTime`

### 技术细节

#### 时区处理原则
- **问题根源：** 手动加8小时的方式是错误的
- **正确方案：** 
  - 对于需要本地化的时间：使用 Intl API 指定 `timeZone: 'Asia/Shanghai'`
  - 对于需要与数据库一致的时间：直接使用UTC方法读取

#### 数据流
1. Notion API 返回 ISO 8601 格式的 UTC 时间（如：`2025-11-30T12:58:00.000Z`）
2. 前端使用UTC方法直接读取，不做转换
3. 显示格式：`2025年11月30日 20:58`（与Notion数据库完全一致）

## 经验总结

1. **时区处理要谨慎**
   - 不要手动计算时区偏移
   - 使用标准API（Intl.DateTimeFormat）
   - 或直接使用UTC方法

2. **数据一致性**
   - 前端显示应与数据库保持一致
   - 明确数据的时区来源

3. **完整性检查**
   - 状态变更时要考虑相关字段的更新
   - formData 要包含所有必要字段
