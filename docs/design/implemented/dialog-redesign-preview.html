弹窗体验重设计

当前项目使用浏览器原生 confirm / alert，样式不受品牌控制且暴露 pages.dev 域名前缀。本方案将 9 个文件中的 23 处原生调用，统一替换为自绘对话框 + Toast 通知两套系统，以下为三套候选风格，可实时交互体验。

1现状诊断

workbench-22i.pages.dev 显示
确认完成任务「交房租-13800」？
视觉割裂

系统默认灰白样式，与产品的紫色品牌体系完全脱节，字体、圆角、色彩均不可控

暴露域名

顶部强制显示「xxx.pages.dev 显示」，显得廉价且降低用户对产品的信任感

无动效无语义

生硬弹出、无过渡动画；alert 无法区分成功/失败/警示，也不支持图标与富文本

阻塞与失控

confirm/alert 阻塞主线程 JS 执行，样式无法跟随系统更新迭代，无法统一维护
